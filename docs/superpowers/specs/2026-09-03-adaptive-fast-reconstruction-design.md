# 自适应快速重建设计

## 背景

当前图片、扫描 PDF 和图片版 PPT 的视觉流程在 OCR 后较早进入 Grounding DINO、prompted/automatic SAM、残差轮次、hole recheck 和可能的第二次视觉 pass。资源隔离还会反复启动 OCR、DINO、SAM、LaMa worker。PDF 入口默认把每页先栅格化，Host Agent 可能在页面质量闭环中等待或重试。

结果是复杂页面的本地计算、进程冷启动、磁盘/序列化开销和 Agent 等待相互叠加。目标不是简单降低模型参数，而是在保证当前 Strict 流程质量基线的前提下，减少不必要的全图推理和重复修复。

## 目标

- 常规图片在模型预热后达到秒级目标；首次运行单独记录模型加载时间。
- 15 页原生 PDF 进入低分钟级目标；扫描或复杂 PDF 进入分钟级目标，具体数值按硬件和页面复杂度基准化。
- 正常页面不进入 Host Agent，不产生不必要的 LLM token 消耗。
- 不允许整页图片作为质量或超时兜底。
- 输出视觉质量不低于当前 Strict 基线；质量门禁失败时只局部升级，不放行错误组件。
- 成功任务默认只保留最终 PPTX 和最小恢复状态；诊断证据按需保留。

## 非目标

- 不在本轮猜测或复制 Codia 的具体闭源模型。
- 不以降低分辨率、关闭所有质量检查或强制并行 GPU 推理换取速度。
- 不要求任意照片内部的每个语义细节都变成矢量对象；无法可靠拆分的区域仍需保持为独立的局部图像组件。

## 质量契约

整页图片 fallback 从产品流程中删除。每页必须输出可编辑对象：文字、规则形状、图片框和可可靠识别的视觉对象应拆分；复杂或不确定区域可作为独立的局部图像图层，保持视觉像素、位置和层级正确。若局部重建仍无法通过质量门禁，任务应明确失败并保留诊断，而不是静默输出低质量结果。

当前 Strict 流程作为回归基线。Fast 路径只有在同一输入上的视觉差异、文字位置/内容、组件覆盖率、PPTX 重开结果均不劣于基线时，才允许成为默认路径。

## 处理架构

```text
输入
  -> 输入/页面分类
      -> 原生 PDF 对象通道
      -> 扫描 PDF / 图片视觉通道
  -> 低成本页面理解
  -> 直接重建确定对象
  -> 仅对不确定区域执行 prompted SAM
  -> 局部背景修复
  -> PPT 渲染回图和局部质量门禁
      -> 通过：发布
      -> 失败：局部升级并重试
      -> 预算耗尽：组件级保真输出或明确失败
```

页面路由器是本地确定性模块，不调用 Host Agent。它只回答“能否直接重建、哪些区域需要分割、是否需要严格流程”，并返回置信度和可解释原因。

## 页面理解与路由

路由器使用以下输入：

- PDF 是否包含真实文字、字体、矢量路径、图片 XObject 和变换信息；
- OCR 文本数量、平均置信度、文字覆盖率和版面方向；
- 矩形、直线、表格、纯色块等规则几何比例；
- 低分辨率预览的边缘密度、颜色复杂度和连通区域数量；
- 透明、重叠、旋转、阴影、扫描噪声和压缩伪影。

路由类型：

1. 原生 PDF：优先提取文字、字体、字号、颜色、图片、路径、transform 和 z-order，不做全页 OCR/SAM。
2. 简单图文页：OCR、几何和颜色分析直接生成对象，只对少量不规则区域分割。
3. 普通图片或扫描页：低成本理解后执行局部 prompted SAM。
4. 复杂低置信度页：进入 Strict 视觉流程，但仍使用局部质量结果决定是否需要 automatic SAM、residual 或 hole recheck。

路由错误不得直接导致低质量发布。最终渲染质量门禁是唯一放行条件。

## 选择性分割与背景修复

- 默认关闭全图 automatic SAM。
- Grounding DINO 只为需要独立边界的候选区域提供提示。
- prompted SAM 只接收局部 crop、box 或 point prompt，避免重复处理整页。
- residual 默认最多一轮，只有质量指标改善才允许继续；不再固定执行三轮。
- hole recheck 只对 mask 不稳定或质量报告指出孔洞的组件执行。
- 小文本孔洞和小面积缺口继续使用 OpenCV/local fill。
- 同页需要大模型修复的 mask 合并后最多调用一次 LaMa，结果缓存供后续阶段复用。

## Host Agent 边界

Host Agent 不进入正常页面热路径。只有本地质量门禁指出结构冲突、文字与组件重叠或局部重建异常时，才提交结构化指标、异常 crop、差异图和少量组件元数据。禁止重复发送完整源图、全部 mask 和所有中间日志。Agent 不能无限重试；每一轮必须有可验证的质量改善。

## Worker 与并发

OCR、Grounding DINO、SAM、LaMa 改为任务级常驻 worker。模型在任务开始时加载一次，页面请求通过队列传递，避免逐页 Python/CUDA 冷启动、PNG 往返和 base64 mask 复制。

CPU 预处理和 PDF 对象提取可以并行；4060 8GB 上 SAM Large 保持受控的单 GPU 队列，不同时运行多个重页面。页面状态独立推进，单页异常不能阻塞其他页面。

## 时间预算与失败处理

每页记录路由、阶段和累计耗时。Fast 阶段超出预算时停止无效重试，转入局部 Strict 处理；Strict 阶段也只能继续局部加严、组件级保真输出或明确失败，禁止整页图片 fallback。任务必须支持取消、逐页进度和失败页定位。

## 中间产物

运行期间只写入恢复和质量门禁必需的状态。`source-text-mask.png`、背景中间图、residual diagnostics、worker request/result 等放入临时工作目录；成功发布后清理。失败页保留最小诊断包，调试模式才保留完整 mask、差异图和中间 JSON。最终用户默认只接收 PPTX 和简短运行摘要。

## 性能与质量指标

每页至少记录：总耗时、PDF render、OCR、DINO、SAM、LaMa、worker 启动次数、候选数量、residual 次数、Host 等待时间、token 使用量、输出组件数和 fallback/失败原因。

基准集必须包含原生文字/矢量 PDF、扫描 PDF、图片版 PPT、简单图文图片和复杂透明/阴影图片。对 Fast 与 Strict 比较：

- p50/p95 单页耗时和 15 页总耗时；
- 首次加载与预热后耗时；
- OCR 内容和位置正确率；
- 组件覆盖率、边界质量和背景残差；
- PPTX 重新打开和再次渲染成功率；
- Host token/page 和进入 Agent 的页面比例。

发布门槛：Fast 的质量指标不得低于 Strict 基线；若指标不达标，只能收紧路由或增加局部精修，不能放宽质量门禁。

## 分阶段实施

1. 加入完整性能/质量埋点，建立当前 Strict 基线。
2. 实现页面路由器和直接重建路径，保留 Strict 作为局部升级路径。
3. 关闭默认 automatic SAM，改为按需 prompted SAM、质量驱动 residual 和页面级 LaMa。
4. 将模型 worker 常驻化并加入页面独立队列、取消和进度。
5. 增加原生 PDF 对象通道和混合页面分流。
6. 增加成功后清理和失败页最小诊断保留。
7. 用真实用户样本完成 Fast/Strict 回归，达到指标后才切换默认路径。
