# P2.3 通用组件 Agent 重建设计

## 状态

本设计于 2026-07-31 经用户逐段确认。它解决当前 P2.2 在组件与文字重叠时整页执行 `text-only fallback`、导致组件候选全部清零的问题。

P2.3 的目标不是针对表格或科研绘图增加特例，而是为任意图片建立通用的语义组件层级，由视觉 Agent 决定“应该怎么拆”，由传统视觉算法精确执行，由确定性质量门禁决定结果能否交付。

## 已确认约束

1. 支持两种互不冲突的 Agent Provider：宿主视觉 Agent 与可选本地视觉模型。
2. Skill 默认使用宿主视觉 Agent，不要求额外下载视觉语言模型。
3. 本地 Provider 用于完全离线或无人值守运行，必须显式安装模型。
4. 每页先执行一次初始分割，随后最多执行 5 个批量重修轮次。
5. 已通过组件立即冻结；失败组件才进入下一轮。
6. 无法稳定细拆时折叠为完整、独立、可移动的父组件，不清空整页组件。
7. 完整父组件也无法无损提取时保留原页并明确报告，不能输出带残影、重影、阴影或残缺的结果。
8. 图片、PDF、图片版 PPTX 和包含原生对象的 PPTX 共用同一套组件重建策略；原生 PPTX 的未命中对象和页面保持不变。

## 非目标

- 不承诺把任意视觉对象转换为 PowerPoint 原生矢量路径、图表或 SmartArt。
- 可靠文字继续转换为原生文本框；组件默认是独立透明图片对象或对象分组。
- 线条、节点和规则几何可以作为子组件提取，但本阶段不强制转为原生 PowerPoint 线条或形状。
- 不引入静默的低质量 `rule-only` 降级。
- 不允许 Agent 绕过像素所有权、视觉差异或 PPTX 结构门禁。

## 方案选择

### 方案 A：纯规则/CV 自适应

根据面积、颜色、连通性和文字重叠率动态调参。它本地、可复现，但无法稳定理解多个碎片是否属于同一个语义整体；继续增加规则会形成针对样例的补丁系统。

### 方案 B：本地或宿主 Agent 规划，CV/SAM 执行，确定性门禁验收

Agent 查看原图、编号掩码、OCR 归属、组件关系和差异图，只输出结构化修复动作。CV/SAM 执行动作，质量门禁验证结果。这是选定方案。

### 方案 C：端到端多模态模型直接重建

大型模型直接生成组件、掩码和 PPT 对象。它难以精确控制像素边界、资源占用高、输出难复现，不适合作为稳定主路径。

## 通用语义组件层级

每页建立语义对象树：

```text
页面
├── 背景
├── 父组件 A
│   ├── 子组件 A1
│   ├── 子组件 A2
│   └── 关联文字
├── 父组件 B
└── 独立文字
```

Agent 使用以下通用证据判断父子、兄弟、文字归属和合并关系：

- 掩码的包含、相交、邻接和间距；
- 颜色、边框、阴影和纹理连续性；
- 对齐、网格、重复结构和连线连续性；
- OCR 框与视觉区域的空间归属；
- 整页语义和对象是否需要组合后才完整；
- 拆分后每个部分能否独立表达；
- 当前重建与原图的区域差异。

表格、科研绘图、人物、海报、UI、流程图、地图、插画和普通照片都使用这套关系模型，不按文件名或固定类别走专用分支。

## 像素所有权

1. 每个可见源像素只能由背景、一个活动组件或一个可编辑文字对象负责。
2. 父组件和它的子组件不能同时渲染。
3. 子组件全部通过门禁时输出子组件，父组件仅保留分组元数据。
4. 任意子组件在 5 轮内无法稳定修复时，停用该父级下的子组件并输出完整父组件。
5. 文字转为可编辑对象后，原始文字及抗锯齿边缘必须从背景和活动组件中清除。
6. 组件的阴影、半透明边缘和抗锯齿过渡属于组件；背景不能保留其副本。
7. 所有权校验失败时不得组装最终 PPTX。

这里的“唯一所有权”约束源图中的前景证据，而不是禁止正常 Alpha 合成。半透明组件下方仍可存在修复后的背景，但源图里的组件颜色、阴影和边缘只能由该组件贡献一次，不能同时残留在背景中。

## Agent 证据与动作协议

每个重修轮次生成不可变证据包：

```text
component_agent_request.json
source.png
numbered-masks.png
ocr-overlay.png
ownership.png
reconstructed.png
difference.png
component-graph.json
quality-report.json
```

请求记录输入 SHA-256、页 ID、Provider、轮次、候选 ID 和每个证据文件的 SHA-256。Agent 只能引用请求中存在的对象。

统一的 `component_plan.json` 至少包含：

- `schema_version`；
- `page_id`；
- `provider`；
- `repair_round`，范围为 1 到 5；
- `request_sha256`；
- 动作列表；
- 每个动作的对象 ID、置信度和证据说明。

允许的动作只有：

- `accept`；
- `merge`；
- `split`；
- `expand`；
- `shrink`；
- `retry_with_box`；
- `retry_with_points`；
- `attach_text`；
- `collapse_to_parent`。

Agent 不写掩码、不修改图片、不直接生成 PPTX。执行器拒绝未知动作、越界坐标、重复对象、不匹配的 Provider、错误轮次、过期请求或哈希不一致的计划。

## 有界重修循环

```text
初始 OCR/CV/SAM
→ 构建组件树和证据包
→ Agent 批量规划失败组件
→ CV/SAM 执行局部修复
→ 确定性质量门禁
→ 冻结通过组件
→ 未通过则进入下一轮，最多 5 轮
```

- 初始分割不计入 5 次。
- 每轮一次处理本页所有未通过组件，不按组件各运行 5 次。
- 已冻结组件的掩码和所有权不能被后续轮次修改。
- Agent 返回空动作、重复相同计划或不存在可执行修复时提前停止。
- 第 5 轮后仍失败的子组件折叠为完整父组件。
- 父组件门禁仍失败时页面状态为 `preserved_with_warning`，保留原页。

## 双 Provider

### Host Provider

`agent_provider=host` 是 Skill 默认模式。

- 不导入、不下载本地视觉语言模型。
- Runtime 生成证据包后进入 `awaiting_agent`。
- Skill 要求 Codex、Claude Code 或其他宿主读取本地诊断图并提交 `component_plan.json`。
- 宿主必须支持视觉输入、本地文件读取、工具调用和结构化输出；能力握手失败时在真实页面处理前停止。
- 宿主服务可能接收诊断图片，README 必须明确隐私边界。

Host 流程：

```text
image2editable run execute RUN_DIR
→ awaiting_agent
→ image2editable agent next RUN_DIR
→ 宿主查看证据并生成计划
→ image2editable agent record RUN_DIR --plan PLAN.json
→ image2editable run execute RUN_DIR
```

Skill 自动编排上述循环，普通用户不需要逐个指定组件。

### Local Provider

`agent_provider=local` 用于完全离线或无人值守运行。

- 不读取宿主会话状态。
- 模型缺失时明确停止，不在转换过程中突然下载。
- 模型通过显式安装命令下载，支持空间检查、断点续传和哈希校验。
- 第一版适配器以 `Qwen/Qwen3-VL-2B-Instruct` 作为待验收基线；只有通过本设计的真实文件和资源门禁后才标记为稳定支持。
- 支持的模型来自版本化兼容目录。核心推荐命令根据硬件和兼容目录选择“最新且经项目验证”的条目，Skill 只展示该结果并请求用户确认，不能根据模型记忆任意选择刚发布的模型。
- OCR、DINO、SAM、LaMa 和本地 Agent 分阶段、分进程运行，重型模型不同时驻留。

模型管理入口：

```text
image2editable models recommend --json
image2editable models install agent
image2editable models status
```

推荐命令读取显存、内存、磁盘、CUDA、PyTorch 和 Transformers 版本；安装前必须显示模型、下载量、缓存位置和兼容性。

### Provider 隔离

1. `prepare` 时将 Provider 写入任务清单，一次 Run 不可中途切换。
2. Host 与 Local 计划记录不同来源，但使用同一个 JSON Schema、执行器和门禁。
3. Host 模式不加载本地模型依赖，也不检查或修改本地 Agent 模型缓存。
4. Local 模式不读取 Host 决策或宿主会话。
5. 不自动回退到另一 Provider；切换必须新建 Run。
6. 中断恢复必须保持 Provider、输入 SHA-256 和证据哈希不变。
7. 执行租约保证两个进程不能同时领取同一页或同一轮次。

## 自适应质量门禁

门禁根据页面自身的分辨率、对象相对面积、局部对比度、噪声、边缘密度、线宽、阴影范围、OCR 字号和候选相对改善进行归一化判断。它不使用“某个文件类型固定一个阈值”的策略。

同时保留不可突破的安全条件：

- 父子同时渲染；
- 大面积像素重复或缺失；
- 明显文字重复；
- 组件越界或遮挡受保护原生对象；
- 背景仍保留组件阴影、文字或边缘副本；
- 输出 PPTX 无法重开或结构变化；
- 最终渲染超过视觉质量上限。

Agent 可以选择修复策略，不能修改或批准绕过安全条件。

## 最终状态和报告

每个父组件最终只能处于以下状态之一：

- `children_accepted`：可靠子组件已输出；
- `parent_preserved`：细拆失败，但完整父组件已独立提取；
- `page_preserved_with_warning`：父组件也无法无损提取，保留原页。

运行报告记录：

- 初始候选数；
- 合并、拆分和重修次数；
- 最终父组件数与子组件数；
- 每轮的动作、质量变化和冻结对象；
- 每个组件的最终状态和降级原因；
- 文字、阴影、残影、透明边缘和所有权风险；
- Provider、模型或宿主能力信息；
- 资源峰值和诊断目录。

检测到有效组件但最终组件数为零时，只有显式 `page_preserved_with_warning` 才合法；不能以普通成功状态隐藏整页降级。

## 资源与失败处理

- 重型页面保持串行。
- 每个重型模型运行在独立子进程中，退出作为确定的内存和显存释放边界。
- 运行前根据可用内存、显存和临时磁盘空间检查安全预算；不足时在加载模型前停止。
- 五轮重修共享页面级资源预算，Agent 无权延长轮次或扩大预算。
- 普通失败保留诊断；重试或恢复只清理 Run 内已验证归属的未完成产物。
- Provider、请求、计划、输入和输出均使用哈希绑定，拒绝过期或跨 Run 复用。

## Skill 与 README

项目 Skill 必须：

- 默认选择 Host Provider；
- 声明宿主必须支持视觉输入；
- 执行视觉能力握手；
- 读取 `agent next` 返回的绝对证据路径；
- 只提交符合 Schema 的动作计划；
- 自动执行最多 5 轮；
- 不允许人工抬高置信度或绕过门禁；
- 当用户选择 Local Provider 时调用硬件推荐命令，并在下载前取得明确同意。

判断和执行代码属于 Python Runtime；Skill Markdown 只保存工作流、约束、工具顺序和失败处理。

README 必须说明：

- Host 与 Local 的适用场景；
- 完整命令和状态流；
- Host 的视觉能力要求和隐私边界；
- Local 的模型、下载量、硬件要求、缓存和离线行为；
- Provider 不可在同一 Run 混用；
- 每页 5 轮上限；
- 父组件回退和页面保留行为；
- 两种模式的稳定性状态。任一模式未通过真实验收时必须标为实验性。

## 测试与发布门禁

### 通用语料

测试覆盖照片、人物、海报、卡片、UI、表格、图表、流程图、科研绘图、公式、密集连线、地图、插画、图标组合、低对比度、渐变、透明、阴影和抗锯齿对象，以及图片、PDF、图片版 PPTX 和混合原生对象 PPTX。

保留不参与调参的隐藏验收集，避免针对 `test1.pptx` 或单个 PDF 优化。

### 自动化测试

- 同一个 Schema 对 Host 记录回放和 Local 模拟 Provider 生效；
- Provider 在 Run 创建后不可切换；
- Host 模式在未安装本地 Agent 模型时仍可完整运行；
- Local 模式在没有宿主会话时仍可完整运行；
- 两种模式不会导入对方的可选依赖或读取对方状态；
- 每页最多 5 个批量轮次；
- 冻结组件不会被后续轮次修改；
- 父子不会同时渲染；
- 有效组件不会无原因从非零变为零；
- 文字、阴影、边缘和透明像素不会在背景与组件中重复；
- 输出 PPTX 可重开，页数、尺寸、备注、原生对象和未命中页面保持正确；
- 中断、恢复、重试和并发租约保持安全。

### 真实 Provider 验收

- Host：至少使用一个支持视觉的宿主完成能力握手和完整端到端转换；
- Local：在安装实际模型后完成端到端组件判断、五轮循环和进程释放检查；
- 两种模式使用相同真实文件和相同确定性门禁；
- 在 8GB 显存、16GB 内存目标机上验证不会再次造成内存或磁盘持续 100%；
- 最终输出逐页渲染检查重影、残影、阴影、孔洞、缺失、错误拆分和文字重复。

Host 与 Local 都通过真实验收后才标记为稳定可用；任一模式仍为占位实现时不得在 README 中宣称完成。

## 实现顺序

1. 引入统一组件请求、计划和 Provider 契约。
2. 将当前页级 `component_text_overlap` 降级改为逐组件状态与完整父组件路径。
3. 实现五轮批量重修状态机和冻结规则。
4. 接通 Host Provider 的 `awaiting_agent` 工作流及 Skill。
5. 接通 Local Provider 的隔离进程和模型管理。
6. 完成共同质量门禁、报告、README 和 CLI 帮助。
7. 运行通用、隐藏及真实文件验收；通过后再标记稳定。
