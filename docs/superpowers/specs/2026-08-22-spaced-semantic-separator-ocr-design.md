# 空格语义分隔符 OCR 保留设计

## 背景与证据

`pdf-mixed-page-sizes` 第 2 页的源标题是 `LETTER PORTRAIT / MIXED SIZE`，但生成的 PPTX 中变成了 `LETTER PORTRAIT MIXED SIZE`。完整渲染检查确认斜杠缺失，而结构化 benchmark 仍然误报通过。

诊断结果表明：隔离调用原始 OCR 能以 `0.9946060180664062` 置信度识别完整标题；完整 `detect_text(...)` 流程却在 `_filter_noise` 中把含 `/` 的全大写标题判为乱码。后续 targeted OCR 只恢复了不含斜杠的文本，最终导致语义标点丢失。文字遮罩几乎覆盖斜杠区域，因此 presentation layer 也无法再把它作为视觉组件补回。

## 目标

保留高置信度标题中具有明确左右语义的空格分隔 `/` 和 `-`，使它们继续进入原生可编辑文本层，同时不放宽现有噪声、warning 或 benchmark 失败门禁。

## 非目标

- 不放宽文字遮罩，也不把斜杠改成栅格回退组件。
- 不修改 OCR 引擎、模型或 targeted OCR 的整体流程。
- 不接受任意标点组合，不削弱现有全大写乱码过滤。
- 不修改 release benchmark 的组件数、文本数、warning 或失败阈值。

## 设计

在 `scripts/text_detect.py` 增加一个小型判定函数，用于识别“空格语义分隔符文本”。仅当以下条件同时满足时返回真：

- 分隔符只允许 `/` 或 `-`，且两侧都有空白；
- 每个分隔符左右两侧都存在有意义的字母、数字或中日韩文字，且每侧至少有两个此类字符；
- 不允许重复分隔符序列；
- 不允许同时出现 `:`、`;`、`.` 或反斜杠等当前乱码规则关注的其他分隔符。

在 `_filter_noise` 的全大写乱码分支中，仅对满足该判定的文本豁免“含乱码分隔符即拒绝”这一项。现有置信度、有效字符比例、竖排、重复字符和其他噪声检查保持不变。现有 `.strip(...)` 只处理边缘标点，内部 `/` 或 `-` 会原样保留。

同样的修改需要同步到 `skills/image-to-ppt/scripts/text_detect.py`，并保持两个运行入口字节一致。

数据流变为：原始 OCR 完整标题 → `_filter_noise` 保留合法空格分隔标题 → 样式与文字遮罩处理 → 原生文本框包含分隔符。这样无需添加视觉斜杠组件，也不会改变严格组件语义。

## 测试设计

- `_filter_noise` 保留高置信度 `LETTER PORTRAIT / MIXED SIZE`。
- `_filter_noise` 保留左右语义完整的空格连字符标题。
- 继续拒绝 `MCOULE ST:SETMP`、`API-`、重复分隔符、纯标点、缺少任一侧语义以及低置信度输入。
- 文本结果构建或检测回归测试确认标题和内部 `/` 均被保留。
- 验证根脚本与 skill 镜像文件完全一致。
- 重建 wheel 后，对真实源页执行隔离 OCR smoke test，确认完整标题进入最终文本结果。

## 验证与发布门禁

1. 先运行新增的定向失败测试，再实现最小修复并使其通过。
2. 运行相关 OCR、targeted OCR 和回归测试。
3. 验证根脚本与 skill 镜像哈希一致。
4. 重建并安装 wheel 到 E 盘验证环境。
5. 使用全新的 author 工作目录重新生成 `pdf-mixed-page-sizes`；不复用 author6 状态。
6. 用新产物替换六份页面/轮次计划并重新校验 graph hash。
7. 运行 `tests/test_release_benchmark.py`，再完整渲染两页并执行 `slides_test.py` 和逐页视觉检查。
8. 在新的 benchmark workspace 中完成固定三次严格重复运行；不得放宽 warning 或失败门禁。

只有代码、测试、真实页面语义、完整渲染和三次严格重复运行全部通过后，才把该案例计为完成。

## 回滚

若新增判定产生误保留，只需回退该窄判定及对应测试。此改动不涉及数据格式、计划 schema、模型文件或迁移。
